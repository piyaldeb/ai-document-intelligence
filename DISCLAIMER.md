## AI inside the product

* **Invoice extraction** can use Anthropic's Claude API when `ANTHROPIC_API_KEY` is configured; only then is document text sent to Anthropic. Without a key, a deterministic local extractor is used and no data leaves the deployment.
* **Embeddings** (semantic search) and **OCR** run locally (BAAI/bge-small-en-v1.5, Tesseract).
* AI output can be wrong. The system reduces the risk with schema-constrained output, a grounding check that discards values not printed in the source, an independent rules cross-check and validation rules, and it routes uncertain records to human review. It does not eliminate the risk.

## Evaluation results

* The metrics in [docs/evaluation-report.md](docs/evaluation-report.md) were **actually measured** by running `eval/run_eval.py` against the running Docker stack; no figure was typed by hand.
* They were measured on the **synthetic dataset** with the **rules-based extractor** (no Anthropic API key was available). Expect lower accuracy on messy real-world documents. The Claude extraction path is covered by unit tests with a mocked API but was **not benchmarked**.
* Timings depend on hardware (measured on an 8-CPU laptop, Docker Desktop, 8 GB RAM allocated).

## Security

* `.env.example` contains **development defaults** (e.g. database password `docintel`). Change every secret before exposing the stack beyond localhost. Real secrets belong in `.env` (git-ignored) or a secret manager.
* Authentication is a single service-level API key held server-side by the web proxy. A real deployment needs per-user authentication (SSO/OIDC), roles and TLS.
